## ⚡ 快还是慢，看数据

插入排序挪动的次数正好等于逆序对数：每挪一次，就把一对「前大后小」摆正。已经有序时只比较 n − 1 次、一次不挪，是 O(n)；完全倒序时比较和挪动都是 n(n − 1)/2 次，是 O(n²)；随机打乱时平均挪 n(n − 1)/4 次左右，还是 O(n²)。

## 🧷 稳定，原地，来一个排一个

- **稳定**：只挪严格大于 key 的元素，相等的不挪，所以两个相等的元素排完后先后顺序不变。按成绩排序时，同分的人还保持原来按学号的顺序。「找 bug」里的第二个坑就是把 `>` 写成 `>=` 弄丢了稳定性。
- **原地**：只多用一个 key 变量，O(1) 额外空间。
- **在线**：不用等数据到齐，像摸牌一样来一个插一个，手里的部分随时是排好的。

## 🌍 真实世界里的插入排序

n 很小时，n² 的劣势体现不出来，插入排序没有递归、不占额外内存、对缓存友好，反而比快排、归并更快。所以主流标准库都在小区间里改用它：

- Java 8 的 `Arrays.sort(int[])`（双轴快排 `DualPivotQuicksort`）：长度小于 `INSERTION_SORT_THRESHOLD = 47` 时用插入排序；较新的 JDK 重写了这个类，阈值改成了 44。Kotlin 的 `IntArray.sort()` 在 JVM 上就是调它。
- Java 的 `TimSort`（对象数组、`List.sort`）：少于 32 个元素时直接用二分插入排序。
- Python 的 `list.sort`（Timsort）：少于 64 个元素时整个列表用二分插入排序；更长时，也用它把短的有序段补长。
- C++ libstdc++ 的 `std::sort`：快排把区间切到 16 个以内就停手，最后整体做一遍插入排序。Go 的 `sort.Sort`（pdqsort）在 12 个以内用插入排序。

## 🔧 常见变种

- **二分插入排序**：用二分查找找插入位置，比较次数降到 O(n log n)，挪动次数不变。要保持稳定，得找「第一个比 key 大的位置」。「亲手写」的第二题就是它。
- **希尔排序**：先按大间隔做插入排序，让元素先跳着大致归位，再逐步缩小间隔到 1。
- **链表插入排序**：链表不用挪元素，只改指针，但找位置只能从头走（LeetCode 147）。
