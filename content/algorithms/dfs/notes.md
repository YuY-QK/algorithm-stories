# 深度优先搜索（DFS）：资料

## 1. 解决什么问题

在图（迷宫格子、依赖关系、网页链接）里从一个点出发，沿一条路尽量走深，走不通再退回换路，直到走遍能到的点。常见用途：判断连通、数连通块（岛屿）、检测环、拓扑排序、回溯搜索（枚举所有方案）。它不保证最短路。

## 2. 核心思路

1. 进入一个格子：出界、是墙、已访问就 return false。
2. 标记 visited（面包屑）。
3. 是终点就 return true。
4. 按固定顺序（本关：上、右、下、左）对四个邻居递归；任何一个返回 true 就 return true。
5. 四个都试完 return false，调用栈弹出一层，也就是回溯。

递归和「显式栈 + 每个格子试到第几个方向」两种写法访问顺序完全相同（本关的 `tour` 用后者，`buildTrace` 用前者，测试里互相核对）。注意：只把邻居一次性全压栈的写法（栈里放格子，弹出时才标记）访问顺序一般和递归不同，正确性没问题但顺序不一样。

## 3. 复杂度和性质

| 项目 | 值 |
|---|---|
| 时间 | O(V + E)；网格上 O(h·w) |
| 空间 | visited O(V) + 调用栈，最坏深度 O(V) |
| 最短路 | 不保证 |
| 递归深度 | JVM 默认栈大约能撑 1.8 万层递归（栈帧小的时候，随 -Xss 变化），大网格要用显式栈 |

对比 BFS：BFS 用队列、一圈圈扩、无权图最短路；DFS 用栈或递归、一条路走到底、省宽度的内存、适合连通性/环/拓扑/回溯。

## 4. 变种和易错点

**变种**
- 洪水填充 / 数岛屿（LeetCode 200）：外层扫描所有格子，遇到没访问的陆地计数并 DFS 淹掉整座岛。
- 回溯 / 全部路径：进格子标记，退出时擦掉标记，才能枚举所有简单路径（练习的 `countPaths`）。
- 拓扑排序：按完成时间（退出时间）的倒序。
- 环检测：有向图用三色（未访问 / 在栈上 / 已完成），碰到在栈上的点就是环。
- 迭代加深 DFS（IDDFS）：限制深度逐步加深，兼顾 BFS 的最短性和 DFS 的省内存。

**易错点**（关卡「找 bug」讲了前三条）
1. 忘记标 visited：`// visited[r][c] = true`，两个格子互相递归，StackOverflowError。
2. 边界只检查一边：`if (r < 0 || c < 0) return false`，r ≥ h 或 c ≥ w 时 `grid[r][c]` 越界。要用 `r !in grid.indices || c !in grid[0].indices` 一起管；检查边界必须在读 grid 之前。
3. 忽略递归返回值：`dfs(...)` 前没有 `if (...) return true`，找到后还在乱走，最后返回 false。
4. 回溯枚举路径时忘记擦掉标记，会漏掉路径；而只求连通时不能擦，否则指数级重复。
5. 在 visited 之前就递归进入邻居（先递归后检查），在带环的图里同样无限递归。
6. 递归太深：1000×1000 空地 DFS 可能超过栈深度，改显式栈。

## 5. 真实应用

- 画图软件油漆桶（洪水填充）。
- 构建工具和包管理器的依赖排序、循环依赖检测（拓扑排序）。
- 数独、八皇后、N 皇后等回溯搜索。
- 随机 DFS 迷宫生成（本关挑战的山洞就是这样生成的）。
- Tarjan / Kosaraju 求强连通分量。

## 6. 关卡讲法建议

- 看：用面包屑和「退回路口」讲回溯；最后一页和 BFS 的水波对比，强调「能找到，不一定最近」。
- 玩：顺序固定（①上②右③下④左），做错时摇头或让该走的方向透光；数岛让孩子体会「一次涂一整块」。
- 做：调用栈和 visited 一起看；猜下一步分前进、回溯（退到哪个路口）、到终点三种。
