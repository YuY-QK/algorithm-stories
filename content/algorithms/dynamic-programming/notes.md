# 动态规划（爬楼梯）：资料

> 写这份资料时没有联网查证，下面的事实凭可靠知识写成，爬楼梯的数字、调用次数、网格路数都在引擎测试和 `dynamic_programming.py` 里用计算核对过。出处细节和具体系统的说法没法用计算核对的，标了「待核实」。

## 1. 解决什么问题

**动态规划**（dynamic programming，DP）是一种解题思路：把大问题拆成相互重叠的小问题，每个小问题只算一次，答案记在表里，大问题直接用表里的答案拼出来。

本关用的例子是爬楼梯：每次跳 1 级或 2 级，到第 n 级有几种跳法（LeetCode 70）。

## 2. 核心思路

三步：

1. **定义状态**：`dp[i]` 表示什么。这里是「到第 i 级的跳法数」。
2. **写转移**：`dp[i]` 怎么由前面的格子算出来。到第 i 级的最后一步，要么从 i-1 跳 1 级来，要么从 i-2 跳 2 级来，两类跳法不重叠也不遗漏，所以 `dp[i] = dp[i-1] + dp[i-2]`。
3. **定起点**：`dp[0] = 1`（站着不动算一种），`dp[1] = 1`。

两个适用条件：

- **重叠子问题**：不记答案的递归会把同一个小问题反复算。本关调用树里「第 3 级」「第 2 级」出现了好几次。
- **最优子结构**：大问题的答案由小问题的答案拼出来。

两种写法：

- 自顶向下（记忆化）：写递归，算完存进表，再遇到先查表。
- 自底向上（填表）：从最小的问题开始按顺序填，没有递归。

## 3. 复杂度和性质

| 写法 | 时间 | 空间 |
|---|---|---|
| 不记答案的递归 | 调用次数 2·ways(n) − 1，指数级（约 1.618ⁿ） | 递归深度 O(n) |
| 记忆化 | O(n)，共 2n − 1 次调用 | O(n) 表加 O(n) 递归栈 |
| 填表 | O(n) | O(n) |
| 滚动变量 | O(n) | O(1) |

具体数字（本关测试核对过）：n = 6 时不记 25 次、记 11 次；n = 30 时不记 2,692,537 次、记 59 次。

爬楼梯的跳法数 ways(n) 是斐波那契数 F(n+1)（F(1) = F(2) = 1）。Long 能装下 ways(91)（约 7.5 × 10¹⁸），ways(92) 约 1.22 × 10¹⁹ 会溢出（Long 上限约 9.22 × 10¹⁸）。

**本关的另外两题**

- `minCostClimbing`（LeetCode 746）：站在第 i 级往上跳要付 `cost[i]`，可从第 0 或第 1 级出发，目标是第 `cost.size` 级。`dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])`，`dp[0] = dp[1] = 0`，答案 `dp[n]`。和爬楼梯的区别：转移里「加」换成「取小的」，问题从「数个数」变成「求最优」，这才是最优子结构的味道。
- `uniquePathsWithObstacles`（LeetCode 63）：二维 dp，`dp[r][c] = dp[r-1][c] + dp[r][c-1]`，石头是 0。没有石头时答案是组合数 C(r+c, r)。

## 4. 常见变种和易错点

**变种**

- 每次可跳 1、2、3 级：`dp[i] = dp[i-1] + dp[i-2] + dp[i-3]`。
- 有坏掉的台阶不能踩：坏台阶 `dp[i] = 0`。
- 硬币找零（LeetCode 322）：`dp[x] = min(dp[x - c] + 1)`。贪心关卡的「动态规划兜底」就是它。
- 0/1 背包、最长公共子序列、编辑距离：二维 dp 表。

**易错点**（本关「找 bug」讲了前三条）

1. 初始值写错：`dp[0] = 0`。`dp[0]` 的含义是「什么都不做有几种方案」，数方案数时是 1，求最小值时是 0，求最大值时常是 0 或负无穷，要看问题。写错整张表都错。
2. 循环起点不对：`for (i in 1..n)`，读 `dp[i-2]` 时下标是 -1。初始值写了几个，循环就从第几个之后开始。
3. 数组开小：`LongArray(n + 1)` 在 n = 0 时没有 `dp[1]`。要么多开一格，要么单独处理 n ≤ 1。
4. 溢出：方案数增长很快，要用 `Long`，甚至对某个数取模（LeetCode 上常见）。`Int` 在 n = 46 就溢出（ways(46) = 2971215073 > 2³¹ − 1）。
5. 状态定义含糊：写 `dp[i]` 前先用一句话说出它的含义，转移和起点都是从这句话推出来的。
6. 递归不加记忆：看起来对，n = 40 就慢得动不了（调用次数 3.3 亿）。

## 5. 真实应用

**生活**：算价格最优的购物组合、规划最省力的爬楼梯路线、拼车拼单凑满减。（比喻性的说法）

**工程**

- 文本比较：`diff` 求最长公共子序列（LCS）。最早的 Unix `diff`（Hunt 和 McIlroy，1976 年，Bell Labs 技术报告，细节待核实）基于 LCS；Git 默认的 diff 算法是 Myers 的 O(ND) 算法（Eugene Myers，1986），求最短编辑脚本，和 LCS 是同一类问题的另一种解法，不是填 dp 表。
- 编辑距离（Levenshtein 距离）：Wagner 和 Fischer（1974）给出了填二维表的算法。拼写检查、模糊搜索常用它或它的变体衡量两个词的相似度；具体某个软件是否这样实现，待核实。
- 序列比对：Needleman–Wunsch（1970，全局比对）和 Smith–Waterman（1981，局部比对）都是动态规划，用于生物信息学比较 DNA、蛋白质序列。
- 背包问题：0/1 背包用 dp 表，时间 O(物品数 × 容量)，是「伪多项式」时间。
- 最短路径：Bellman–Ford、Floyd–Warshall 属于动态规划，Dijkstra 属于贪心。地图导航软件实际用什么算法，待核实（一般认为是 Dijkstra/A* 加上预处理的变种，不是这里的 dp 表）。
- Viterbi 算法：隐马尔可夫模型的解码，用于语音识别、词性标注、通信里的卷积码解码。
- 名字的由来：Richard Bellman 在 1950 年代提出。「programming」在这里是「规划、制表」的意思，不是写程序。（关于他为什么选这个名字有一个流传很广的说法，待核实，没有放进关卡。）

## 6. 关卡讲法建议

| 步骤 | 讲法 |
|---|---|
| 看 | 小兔子爬楼梯，每级贴便签。先让孩子看到 1、1、2，再问第 3 级的最后一步从哪来，引出「两张便签加起来」。画面里高亮的两级就是来路。 |
| 玩一 | 数跳法：自己点出第 1～3 级的全部跳法（脚印数字），找到一个就少一个问号；然后猜第 4、5、6 级。猜错时下面两级的便签闪光，不直接给答案。 |
| 玩二 | 便签有多省事：调用树里重复的圆圈（答案之前算过的）自己点出来，点中就贴上便签，下面整棵树变灰。再爬高一级，看两个计数器拉开。 |
| 做 | 逐步执行（dp 表加 Kotlin 代码）、猜下一步（先点来路再选数）、找 bug（初始值、循环起点、数组大小）、亲手写（三题）、挑战（网格数路线填表）。 |
| 延伸 | 重叠子问题和最优子结构、记忆化与填表、O(1) 空间、斐波那契、和贪心的关系、真实应用。 |
