# 选择排序：资料

## 1. 解决什么问题

把一组数据从小到大排好。选择排序是最直观的排序方法之一：每次「选」出剩下里面最小的，放到它该去的位置。

## 2. 核心思路

1. 把数组分成两部分：前面「已排好」的（一开始为空）和后面「未排好」的。
2. 第 i 轮（i 从 0 开始）：在 `arr[i..n-1]` 里找最小值的下标 `minIdx`。做法是先令 `minIdx = i`，再用 j 从 i + 1 扫到 n − 1，遇到 `arr[j] < arr[minIdx]` 就令 `minIdx = j`。
3. 把 `arr[minIdx]` 和 `arr[i]` 交换。现在 `arr[0..i]` 已排好，而且就是全体元素里最小的 i + 1 个，以后不再动。
4. 做 n − 1 轮。最后剩下的那一个一定是最大的，不用再挑。

不变式：第 i 轮开始时，`arr[0..i-1]` 有序，并且其中每个元素都不大于 `arr[i..n-1]` 里的任何元素。

## 3. 复杂度和性质

| 项目 | 值 |
|---|---|
| 比较次数 | 总是 (n−1) + (n−2) + … + 1 = n(n−1)/2，和输入无关 |
| 时间（最好、平均、最坏） | 都是 O(n²) |
| 交换次数 | 最多 n − 1 次（只在 `minIdx != i` 时交换，已经有序时 0 次） |
| 空间 | O(1)，原地排序 |
| 稳定性 | 不稳定（数组上的常见写法） |
| 自适应 | 否，数据接近有序也不会变快 |

具体数字：n = 6 时比较 15 次；n = 1000 时比较 499,500 次，交换至多 999 次。

**交换次数最少**：元素各不相同时，把一个排列排好最少要交换 n − c 次（c 是排列分解成的环的个数）。选择排序每次交换都把正确的元素送到位置 i，这两个元素在同一个环里，交换后这个环拆成两个，所以它的交换次数正好等于 n − c，达到最少。本仓库测试里用广度优先搜索对 2 到 6 个元素的排列做了验证（`tests/selection-sort.test.ts`）。

**不稳定的例子**：[2a, 2b, 1]。第一轮最小的是 1，和 2a 交换，得到 [1, 2b, 2a]，两个 2 的先后顺序反了。原因是长距离交换会越过中间的元素。可以改成「把最小值取出、中间元素整体后移一格再放入」来变稳定，但这样写入次数变成 O(n²)，失去了它的优点。

**和冒泡排序比**：冒泡排序（相邻交换）的交换次数等于逆序对个数，随机排列平均 n(n−1)/4，最坏 n(n−1)/2；比较次数最坏也是 n(n−1)/2，但带「本轮没交换就提前结束」时，已经有序只要 n − 1 次比较。

## 4. 常见变种和易错点

**变种**

- 只做 k 轮：得到最小的 k 个（部分排序），找第 k 小，代价约 k·n 次比较。
- 每轮同时找最小和最大，分别放到两头（双向选择排序），轮数减半，用成对比较的技巧（先把一对元素互相比，再让大的去比最大、小的去比最小）可降到约 3n²/8 次比较。
- 用堆来「选」：堆排序（heapsort），每次取最值 O(log n)，总共 O(n log n)。
- 链表上的选择排序：可以把选出的节点摘下来接到结果链表尾部，这样是稳定的。

**易错点**（关卡「找 bug」用了前三条，每条只改一行，都会排出错的结果）

1. 和错的对象比较：写成 `if (arr[j] < arr[i])`。这样找到的是「最后一个比 arr[i] 小的」，不一定是最小的。例：[4, 1, 3, 5, 2] 会排成 [2, 1, 3, 4, 5]。
2. 内层循环从 0 开始：写成 `for (j in 0 until n)`。已排好的部分也参与比较，`minIdx` 被拉回前面，把排好的换乱。例：[3, 4, 1, 2] 会变成 [4, 3, 1, 2]。
3. 交换没用临时变量：`arr[i] = arr[minIdx]` 之后写 `arr[minIdx] = arr[i]`，原来的 `arr[i]` 丢了。例：[3, 4, 1, 2] 会变成 [1, 1, 1, 2]。
4. `minIdx` 没在每一轮重置成 i（比如定义在外层循环外面，或者初始化成 0）：会拿已排好部分的位置去交换，结果错。
5. 外层循环写成 `0 until n - 2`：少做一轮，最后两个可能没排好。
6. 判断写成 `<=`：结果仍然有序，但一样大的元素会选到最后一个，交换次数可能变多，稳定性也更差。
7. 把交换写进内层循环（每遇到更小的就立刻和 arr[i] 交换）：结果其实是对的，但交换次数变成 O(n²)，丢掉了选择排序「交换少」的优点。

## 5. 真实应用

**生活**

- 按身高排队：每次从没排的人里叫出最矮的。
- 打牌时整理手牌的一种方式：每次从手里挑出最小的一张放到最左边。

**工程**

- 写入代价高的存储：EEPROM、闪存的擦写次数有限而且慢，选择排序写入次数是 O(n)。Wikipedia「Selection sort」条目提到在写入昂贵时选择排序比插入排序等更合适；要把写入降到理论最少可用 cycle sort。
- 小数组、代码体积受限的嵌入式场合：代码极短、不需要额外内存。不过同样场合下插入排序通常更快，标准库对小数组一般用插入排序（如 Java 的 `Arrays.sort` 对基本类型小数组、Python 的 Timsort 里的二分插入排序），而不是选择排序。
- 思想的延续：堆排序（Williams 1964）就是「用堆来做选择」的选择排序；锦标赛排序（tournament sort）也是同一思路。
- 部分排序 / Top-K：k 很小时，做 k 轮选择就能拿到前 k 名。实际工程中更常用堆（如 Kotlin/Java 的 `PriorityQueue`）或 quickselect。

## 6. 关卡讲法建议

| 步骤 | 讲法 |
|---|---|
| 看 | 小熊排糖果：6 颗糖 [5, 2, 6, 1, 4, 3]，每轮从剩下的里挑最小的换到前面，排好的放上盘子。这一组有两轮「最小的已经在最前面」，正好讲到不用换的情况。 |
| 玩 | ① 孩子每轮点出最小的；点错时把点的和真正最小的并排放大比一比；只剩一颗时问「还要挑吗」。② 「小熊的手」：小熊手里拿着目前最小的，一颗颗看后面的，孩子决定换不换，对应代码里的 minIdx。 |
| 做 | 逐步执行（i、j、minIdx、比较和交换次数）；猜 minIdx 停在哪、被改了几次；找 bug（上面 1～3）；亲手写 selectionSort 和 kthSmallest；挑战：自己用最少的交换排好，和选择排序比（它就是最少）。 |
| 延伸 | 比较 n(n−1)/2、交换 ≤ n − 1；不稳定的例子；和冒泡、插入对比；堆排序是升级版。 |
