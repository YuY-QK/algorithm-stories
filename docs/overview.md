## 1. 为什么做

**首先是自己把算法吃透，其次是让孩子提前接触和学习算法。**

公开到 GitHub、写博客、有影响力，都是顺带的收获，不是目标。

由此带来的原则：

- 节奏由自己定，不赶数量。一个算法真正吃透，比做十个更重要。
- 不为发布专门设计流程。做好的东西放在 GitHub 和网站上就够了，博客想写再写。

## 2. 给谁

最重要的用户只有两个：**我自己**和**我的孩子**。

| | 现状 | 需要什么 |
|---|---|---|
| 孩子 | 基本识字，但对图形更容易接受 | 图标、角色、颜色、动画负责讲，文字只做提示；操作简单，点一点、拖一拖就能玩 |
| 我自己 | 想学明白，但看书常看不懂，也懒得做习题，原因是书不够直观、习题不够有趣 | 先直观地看懂，再在好玩的练习里练会，最后能自己写出来 |

两个人要的其实是同一样东西：**先看懂，再在玩的过程中练会**。区别只在深度：孩子玩到「懂规则」就停，我继续玩到「会写代码」。

怎么验证做得好不好：

- 孩子愿意主动玩，能用自己的话（或比划）讲出规则
- 我能脱离演示把算法讲清楚，并独立写出来

其他读者（初学者、学生、工程师）是顺带服务的对象，不为他们单独设计。

## 3. 是什么

**每个算法是一个小关卡，分三步：看、玩、做。**

| 步骤 | 内容 | 谁走到这里 |
|---|---|---|
| 看 | 一个小故事加动画，用图形讲清楚算法在做什么 | 孩子、我 |
| 玩 | 动手操作，在游戏里自己当一回算法 | 孩子停在这里 |
| 做 | 猜下一步、找 bug、亲手写代码，一关一关过 | 我走到这里 |

**不是「读完再做题」，而是「边玩边学会」。** 练习本身就是好玩的部分，不是看完之后的额外负担。「做」这一步的关卡形式举例：

- 猜下一步：演示停住，先猜指针会移到哪里，再揭晓
- 找 bug：给一段有错的代码，看它在动画里怎么跑错，把错误找出来
- 亲手写：自己写一个函数，让它驱动动画，跑通就过关
- 挑战：用最少的步数完成任务，和算法本身的结果比一比

**和原来设想的区别**

- 原来分四个等级（初级、进阶、中级、高级），现在只看「孩子停在哪、我走到哪」。进阶、中级以后想做，可以插在「玩」和「做」之间，不影响整体框架。
- 原来的高级档是「逐步执行、代码、复杂度对比、工程应用」，偏向一本会动的书。现在要把「练」做进去，复杂度和工程应用可以作为通关后的延伸阅读。
