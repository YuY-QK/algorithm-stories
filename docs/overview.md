## 1. 为什么做

**首先是自己把算法吃透，其次是让孩子提前接触和学习算法。**

公开到 GitHub、写博客、有影响力，都是顺带的收获，不是目标。

由此带来的原则：

- 节奏由自己定，不赶数量。一个算法真正吃透，比做十个更重要。
- 不为发布专门设计流程。做好的东西放在 GitHub 和网站上就够了，博客想写再写。

## 2. 给谁

最重要的用户只有两个：**我自己**和**我的孩子**。

| | 现状 | 需要什么 |
|---|---|---|
| 孩子 | 基本识字，但对图形更容易接受 | 图标、角色、颜色、动画负责讲，文字只做提示；操作简单，点一点、拖一拖就能玩 |
| 我自己 | 想学明白，但看书常看不懂，也懒得做习题，原因是书不够直观、习题不够有趣 | 先直观地看懂，再在好玩的练习里练会，最后能自己写出来 |

两个人要的其实是同一样东西：**先看懂，再在玩的过程中练会**。区别只在深度：孩子玩到「懂规则」就停，我继续玩到「会写代码」。

怎么验证做得好不好：

- 孩子愿意主动玩，能用自己的话（或比划）讲出规则
- 我能脱离演示把算法讲清楚，并独立写出来

其他读者（初学者、学生、工程师）是顺带服务的对象，不为他们单独设计。

## 3. 是什么

**每个算法是一个小关卡，分三步：看、玩、做。**

| 步骤 | 内容 | 谁走到这里 |
|---|---|---|
| 看 | 一个小故事加动画，用图形讲清楚算法在做什么 | 孩子、我 |
| 玩 | 动手操作，在游戏里自己当一回算法 | 孩子停在这里 |
| 做 | 猜下一步、找 bug、亲手写代码，一关一关过 | 我走到这里 |

**不是「读完再做题」，而是「边玩边学会」。** 练习本身就是好玩的部分，不是看完之后的额外负担。「做」这一步的关卡形式举例：

- 猜下一步：演示停住，先猜指针会移到哪里，再揭晓
- 找 bug：给一段有错的代码，看它在动画里怎么跑错，把错误找出来
- 亲手写：自己写一个函数，让它驱动动画，跑通就过关
- 挑战：用最少的步数完成任务，和算法本身的结果比一比

**和原来设想的区别**

- 原来分四个等级（初级、进阶、中级、高级），现在只看「孩子停在哪、我走到哪」。进阶、中级以后想做，可以插在「玩」和「做」之间，不影响整体框架。
- 原来的高级档是「逐步执行、代码、复杂度对比、工程应用」，偏向一本会动的书。现在要把「练」做进去，复杂度和工程应用可以作为通关后的延伸阅读。

### 4a. 关卡模板（10-22 定）

每个算法照这个形状做，只是内容不同：

```
看（绘本动画）→ 玩（孩子当主角）→ 做（猜下一步、找 bug、亲手写、挑战）→ 延伸阅读
```

| 步骤 | 形式 | 要点 |
|---|---|---|
| 看 | 像一本会动的绘本，四五个画面 | 每个画面最多一行字，图形和动画负责讲 |
| 玩 | 一到两个小游戏，孩子当主角 | 遵守下面「玩」的原则 |
| 做 | 猜下一步、找 bug、亲手写（本地 Kotlin）、挑战 | 练习做成关卡，一关一关过 |
| 延伸阅读 | 复杂度、真实世界里的用法 | 通关后再看，不挡在前面 |

**「玩」的原则：引导式**

- 不直接告诉答案，用提示和追问让孩子自己发现规律。
- 也不放任乱点：每一下操作都有反馈，把孩子往正确的思路上带。
- 答案预先固定（藏好、盖住），孩子没法中途改主意或耍赖。
- 做错时不说「错了」，而是给一个看得见的提示（晃一下、透出光），让孩子自己再看一眼。
- 以图标、角色和动画为主，文字只做提示；操作以点选为主，能点就不拖。

**样板关：二分查找「小邮差找信箱」**

- **看**：一条街 15 个信箱（15 = 2⁴ − 1，每次点正中间时剩下的总是奇数个，正中间唯一，最多 4 次），小邮差走到正中间，门牌出现箭头，一半信箱变灰，再走到剩下部分的中间，几下就找到。
- **玩法一「藏信」（孩子出题，看邮差怎么找）**：孩子点一个信箱，信飞进去，盖上叶子。小邮差停在某个信箱前，孩子点 ⬅️、➡️ 或 🎉 给他指路；指错时，藏信的信箱透一点光提示。学到的是「每次排除一半」。
- **玩法二「当小邮差」（孩子自己找）**：信由程序藏好，孩子点信箱，门牌显示 ⬅️、➡️ 或 🎉，排除掉的一半变灰；小邮差问「灰色的还要看吗？」，点灰信箱会摇头。几轮之后问「点哪里最快？」，让孩子自己说出「中间」。次数越少星星越多（4 次以内三颗星）。学到的是「点中间最快」。
- **做**：
  1. 猜下一步：给出当前 `lo`、`hi`，点出下一个 `mid` 和被丢掉的一半，连对 5 次过关。
  2. 找 bug：三个常见坑（`while (lo < hi)` 少了等号、`hi = mid` 死循环、`(lo + hi) / 2` 溢出），每关一段有坑的 Kotlin 代码，动画演示怎么跑错，点出错的那一行。
  3. 亲手写：本地实现 `binarySearch` 和变种「第一个大于等于目标的位置」，测试全绿过关。
  4. 挑战：1 到 1000 里猜数，10 次以内猜中。
- **延伸阅读**：为什么最多 log₂n 次；`git bisect` 找出引入 bug 的提交、数据库索引。

### 4b. 「做」用 Kotlin，在本地写（10-22 定）

Kotlin 是日常最熟的语言，学算法时不再额外学一门语言；LeetCode 也支持 Kotlin，学完能直接接上刷题。

| 步骤 | 在哪里 | 形式 |
|---|---|---|
| 看 | 网页 | 故事加动画，代码面板显示 Kotlin 版本 |
| 玩 | 网页 | 点选、拖拽 |
| 做（不写代码的部分） | 网页 | 猜下一步、找 bug、挑战 |
| 做（亲手写） | 本地 IntelliJ / Android Studio | 仓库里放一个 Kotlin 练习项目，每关给出函数框架和测试，写完跑测试，全绿就过关 |

Kotlin 不能直接在网页里运行（Kotlin Playground 要把代码发到 JetBrains 服务器编译，只返回文字输出，难以驱动动画），所以亲手写放在本地。网站本身仍是 Astro + Vue + TypeScript，由 Claude 维护。

二分查找和栈试玩后记了四条反馈，都已改在共享部分，13 关一起受益（详见 `docs/progress.md`）：
