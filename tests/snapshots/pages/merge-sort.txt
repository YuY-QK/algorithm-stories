亲手写

在自己电脑上用 IntelliJ IDEA 或 Android Studio 打开仓库里的 exercises/ 目录，把 mergesort/MergeSort.kt 里的三个 TODO() 换成你的代码：

merge(a, b)：把两个已经排好的数组合成一个新的有序数组。这是整个算法的心脏。
mergeSort(arr)：对半分、递归、再调用 merge，返回排好的新数组，不改动原数组。
countInversions(arr)：变种。数一数有多少对「前面比后面大」。提示：合并时，右边的数先走，说明它比左边剩下的每一个都小。

快还是慢，看数据

n 个数一共要分 log₂n 层，每一层的合并加起来最多比较 n 次，所以总共不超过 n log₂n 次。而且不管输入长什么样（有序、倒序、随机）都是这个量级：最坏也是 O(n log n)。插入和选择排序是 O(n²)，数据一多差距就大得惊人。

数字是比较次数，条形长度用对数刻度绘制。归并取最坏情况的精确值，插入是随机打乱时约 n²/4，选择固定是 n(n − 1)/2。同样排一百万个数，差了一万到两万多倍。

稳定，但要额外的空间
稳定：两边队头相等时取左边的（<=），相等的元素不会越过彼此。「找 bug」里的第一个坑就是写成了 <。
时间有保证：最好、平均、最坏都是 O(n log n)，不像快速排序最坏会退化到 O(n²)。
要额外的空间：合并需要临时数组 tmp，额外空间 O(n)。这是它最大的代价；数组版很难做到原地合并。
递归深度只有 log n：每次对半分，栈很浅，不会溢出（除非像「找 bug」第三个坑那样，出口写错了）。
🌍
真实世界里的归并排序
Java 对象排序：Arrays.sort(Object[])、List.sort 用的 TimSort，是「稳定、自适应的归并排序」：先找出已经有序的片段（run），不够长的用二分插入排序补长，再像归并那样一段一段合并。Kotlin 在 JVM 上对 List 排序（sorted()、sortedBy）最终也走这里，所以是稳定的。基本类型数组 IntArray.sort() 则用双轴快排，不稳定也无所谓。
Python：list.sort 和 sorted 就是 Timsort，原作者是 Tim Peters。
外部排序：数据比内存大时，先把数据切成能装进内存的块，每块排好写到磁盘，再用多路归并把这些有序的块合成一个。数据库排序、大数据的 shuffle 阶段、命令行 sort 处理大文件，思路都是它。
链表：链表不能随机访问，快排不好用，归并排序只改指针、不需要额外数组，是链表排序的首选（LeetCode 148）。
🔧
常见变种
自底向上：不用递归，先把相邻两个合并，再把相邻两对合并……一层一层往上，就是「看」里倒着合并的那一章。
数逆序对：合并时右边的数先走，它就和左边剩下的每个数构成逆序对。顺手数一数，O(n log n) 就能得到逆序对数，而不是暴力的 O(n²)。「亲手写」的第三题。
多路归并：一次合并 k 个有序序列，每次从 k 个队头里挑最小的（用堆，LeetCode 23）。外部排序就是它。
