贪心是什么

每一步都做眼前看起来最好的选择，选了就不改，也不回头。它通常很快、很好写，难的是证明它对：要说明「第一步按贪心选不会错过最优解」，而且「选完以后剩下的还是同一类问题」。

⚡
快，但不一定对

6 种面值时，贪心只要把面值看一遍（同一种拿几枚用除法算）；动态规划要把 1 到 amount 的每个金额都算一遍，金额越大越慢。

✅
什么时候贪心对
对所有金额贪心都拿到最少的面值组合，叫规范（canonical）的币制。美元硬币 1、5、10、25 美分，欧元和小熊的 1、2、5 一组往上翻十倍，都是规范的；人民币现行的 1 角、5 角、1 元、5 元、10 元、20 元、50 元、100 元也是（本关用动态规划逐个金额核对过）。
不规范的例子：1、3、4 凑 6；美元里加一枚 20 美分，凑 40 时贪心拿 25 + 10 + 5，其实 20 + 20 就够；英国 1971 年以前的硬币（3、6、12、24、30 便士等）凑 48，贪心 30 + 12 + 6，两枚 24 的弗罗林就够。
怎么判断：Kozen 和 Zaks（1994）证明，反例如果存在，最小的那个一定比最大两种面值之和小，查到那里就够了（挑战里就是这么查的）。Pearson（2005）还给出了不用逐个金额查的多项式时间算法。
面值里没有 1 时，贪心甚至可能凑不齐：3、5 凑 9，拿了 5 剩 4，再拿 3 剩 1，卡住了，其实 3 + 3 + 3 可以。
🧮
动态规划兜底

凑出 x 最少几枚，看最后一枚是哪种面值：最后一枚是 c，前面就要凑出 x − c。把每个 c 都试一遍取最少，从小到大填表。这就是「亲手写」里的 minCoins：

fun minCoins(coins: IntArray, amount: Int): Int {
2
    val inf = Int.MAX_VALUE
3
    val best = IntArray(amount + 1) { inf }  // best[x]：凑出 x 最少几枚
4
    best[0] = 0
5
    for (x in 1..amount) {
6
        for (c in coins) {
7
            if (c <= x && best[x - c] != inf && best[x - c] + 1 < best[x])
8
                best[x] = best[x - c] + 1  // 最后一枚是 c
9
        }
10
    }
11
    return if (best[amount] == inf) -1 else best[amount]
12
}

其他贪心算法
活动安排：一个会议室，排尽量多互不冲突的会议。每次挑结束最早的那个，可以证明一定最多。
哈夫曼编码：每次把出现次数最少的两个字符合并，得到最短的编码。ZIP 文件用的压缩方法 DEFLATE 里就有它。
Dijkstra 最短路：每次确定离起点最近的那个点。地图导航、网络路由都用它的思路。
最小生成树（Kruskal、Prim）：每次接上最短的、不成圈的边，用最少的线把所有村子连起来。
